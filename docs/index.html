How an LLM gets finetuned — shown with a real run

This walkthrough explains LLM finetuning using an actual QLoRA training run (quantized low-rank adaptation — the memory-saving method Chapter 2 unpacks): BioMistral-7B adapted on a biomedical Q&A dataset of 800 prepared samples, on a single consumer GPU, in about ten minutes. Every chart on these pages is drawn from the real logs and files that run produced — including the part where it went wrong.

The pipeline at a glance

Finetuning is a short assembly line: raw text goes in one end, a small adapter file (a thin set of extra weights that steer the base model without rewriting it) comes out the other. Rounded tinted boxes are artifacts (files you can open); plain boxes are processing steps. Each stage is one chapter.

The run in one picture

Training loss (measured on the data the model learns from) kept falling. Evaluation loss (measured on held-out data the model never saw) went up between the two checkpoints where it was measured. That widening gap is overfitting — the model memorized its 800 examples instead of learning to generalize. Chapter 4 dissects it; this is the honest headline of the run.

Where the numbers come from

This is a real project, not a mock-up. The repository contains the full training artifacts, and each chapter cites its sources:

  • outputs/biomistral-medical/trainer_log.jsonl — loss and learning rate every 10 steps
  • outputs/biomistral-medical/all_results.json — final metrics of the run
  • outputs/biomistral-medical/training_analysis.md — the original overfitting diagnosis
  • configs/biomistral_qlora.yaml — the exact training configuration
  • data/processed/medical_train.json — the 800 training samples themselves

Case-study model: BioMistral-7B finetuned with LLaMA-Factory (QLoRA, 4-bit NF4), January 2026. The finetuned model answers medical questions and is for education and research only — never for clinical use. The subject of these pages is the finetuning process, not medical advice.
